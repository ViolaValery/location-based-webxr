1. INTRODUCTION & MOTIVATION

Why We Built This System

Traditional GIS software is restricted to desktop screens. We built a browser-based bridge for spatial WebXR.

The Problem

KML/KMZ files are standard for geographic data (markers, lines, 3D COLLADA models). Inspecting and editing them directly in the field at real GPS locations has traditionally required desktop software or native apps.

Our Solution

A web-first system: a desktop 3D GIS editor paired with a mobile WebXR/Sensor AR application. Users can inspect geospatial assets at real coordinates and edit them in field POV.

Practical Use Cases

• Field GIS surveying and asset inspection.
• Urban planning: placing 3D models at real coordinates.
• Round-trip editing: edit in mobile AR, reopen in Google Earth.

2. IMPLEMENTATION DETAILS

Data Losslessness & Spatial Mathematics

Solving KML losslessness and GPS-to-3D spatial transformations.

Lossless KML AST (document-model)
  • The Challenge: Re-serializing XML breaks custom Google Earth tags, CDATA blocks, comments, and formatting.
  • Our Approach: Keep raw KML string intact and use DOMParser range lookups to find coordinate substrings.
  • Result: Moving a marker modifies only its specific coordinate substring, preserving 100% of unedited XML data.
Geodetic Bridge (geo-bridge)
  • Coordinates: Converts WGS84 (Lat, Lon, Alt) into Three.js Cartesian meter space using NUE (North-Up-East).
  • Altitude Policies: Handles KML clampToGround, relativeToGround, and absolute height modes.
  • Bi-directional: Converts 3D meter touch-drags back into exact micro-degrees of GPS location.

5. PROBLEMS ENCOUNTERED

Lab Challenges & Solutions

Key obstacles during development and how we solved them.

iOS Safari WebXR & Sensor Security Restrictions

Problem: iOS Safari lacks native WebXR (navigator.xr) and blocks camera & motion sensors on unencrypted http://192.168.x.x local network IPs.

Solution: Built a custom Gyroscope/Compass sensor fallback engine and implemented Cloudflare/HTTPS tunneling workflows for mobile testing.

Nested XML Range Parsing Bug

Problem: Nested KML elements (e.g. 3D <Model> tags containing child tags) caused substring range overlaps during coordinate edits.

Solution: Refactored findFeatureRanges() in document-model to filter out nested child ranges, preserving clean outer element boundaries.

6. WHAT WORKED WELL

Lab Successes

Built an extensive automated unit test suite with 164 / 164 passing Vitest tests across all 9 components, ensuring zero regressions when refactoring.

Origin Private File System (OPFS) & debounced saving provided smooth 60 FPS spatial dragging without disk bottlenecking.
